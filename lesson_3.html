Функции и исключения

def выносит повторяющееся правило в отдельную функцию. Исключения нужны для обработки ожидаемых ситуаций: отсутствие файла, неверный формат или отказ доступа.

Функции, hashlib и обработка файлов python
from pathlib import Path
import hashlib

def is_minimum_length(password: str) -> bool:
    # Учебный пример: проверяем только длину, не реальную стойкость.
    return len(password) >= 8

def sha256_file(path: str) -> str | None:
    try:
        return hashlib.sha256(Path(path).read_bytes()).hexdigest()
    except (OSError, PermissionError) as error:
        print(f"Не удалось прочитать файл: {error}")
        return None
Важно: длина от 8 символов — пример функции из лекции, а не полноценная политика надёжных паролей. Для реального хранения паролей нельзя использовать простой SHA-256 без специализированной функции для паролей.

02 / Изоляция зависимостей

Виртуальное окружение venv

Разные Python-проекты могут требовать разные версии библиотек. venv создаёт отдельный интерпретатор и набор установленных пакетов для каждого проекта.

Без изоляции

Проект A requests 2.x
Проект B requests 3.x
Общие site-packages Конфликт версий

С окружениями

Проект A
.venv A · requests 2.x
Проект B
.venv B · requests 3.x

Пакеты не смешиваются ✓

Создание и установка — PowerShell powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install requests cryptography python-dotenv
python -m pip freeze > requirements.txt
# Выход из окружения:
deactivate
Создание и установка — CMD bat
py -m venv .venv
.venv\Scripts\activate.bat
python -m pip install requests cryptography python-dotenv
python -m pip freeze > requirements.txt
deactivate
Создание и установка — POSIX bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests cryptography python-dotenv
python -m pip freeze > requirements.txt
deactivate
Замечание: активация удобна, но не обязательна: можно запускать .venv-интерпретатор напрямую. Если PowerShell запрещает запуск скрипта активации, лучше использовать CMD или прямой путь к Python, а не ослаблять политику безопасности системы.

Что должно попасть в Git?

✕ .venv/Локальная папка окружения, её пересоздают
✓ README.mdИнструкция по запуску проекта
03 / Конфигурация

Переменные окружения и .env

Настройки приложения и секретные значения не должны быть в исходном коде. Программа читает конфигурацию из своего окружения; локальный файл .env — удобный способ подать эти значения при разработке.

# .env — только ЛОКАЛЬНО, не добавлять в Git!
DB_PASSWORD=example-only-not-a-secret
API_TOKEN=demo-placeholder-token
DEBUG=false
Конфигурация из окружения python
import os
from dotenv import load_dotenv

load_dotenv()
api_token = os.getenv("API_TOKEN")
if api_token:
    print("API_TOKEN загружен")  # само значение НЕ печатаем
else:
    print("API_TOKEN не задан")
Интерактив: загрузка переменной

Переключите наличие переменной. Модель показывает, как работает os.getenv().

os.getenv("API_TOKEN")"demo-••••"
if api_token:True
Вывод программыAPI_TOKEN загружен
Демонстрация не читает настоящие переменные окружения вашего компьютера. Это локальная модель.
Точность: API_TOKEN = "..." в Python создаёт обычную переменную программы, а не переменную окружения. Поэтому последующий os.getenv("API_TOKEN") без настройки окружения вернёт None.

getenv или environ?

os.getenv("API_TOKEN")

Вернёт строку или None, если имени нет. Можно задать значение по умолчанию.

os.environ["API_TOKEN"]

Вернёт строку или выбросит KeyError, если переменная не определена.

04 / Доступ и риск

Почему секреты нельзя хранить в коде

Git сохраняет историю коммитов, а публичные репозитории могут сканироваться автоматическими системами. Удаление строки из последней версии файла не гарантирует удаления её из истории.

1Ключ записали в кодAPI_TOKEN = "..."
2Сделали коммитGit сохранил содержимое
3Отправили в репозиторийКлюч стал доступен
4Ключ обнаруженСканер или другой читатель

Плохой вариант

Антипаттерн (НЕ использовать) python
API_TOKEN = "real-secret-goes-here"
print(API_TOKEN)  # ещё и утечка через лог

Секрет попадает в код, может появиться в логах, снапшотах и истории Git.

Правильнее

Чтение конфигурации python
import os
api_token = os.getenv("API_TOKEN")
if not api_token:
    raise RuntimeError("API_TOKEN не задан")
# Используйте токен, не выводя его в журнал

Секрет передаётся извне; для продакшена используйте менеджеры секретов и минимальные права.

Если секрет уже попал в репозиторий

1Немедленно отозвать / заменить

Сначала ротация ключа, пароля или токена. Считать раскрытый секрет скомпрометированным.

2Оценить воздействие

Просмотреть журналы доступа, возможное использование ключа, связанные права и ограничения.

3Удалить из кода и истории при необходимости

Обычный новый коммит не очищает старые версии. Очистка истории требует координации.

4Включить предотвращение повторов

.gitignore, проверка staged-файлов, secret scanning, ревью и push protection.

Подробный процесс — руководство GitHub по удалению секретов.

05 / Версии и аудит

Git: история, аудит и откат

Git фиксирует состояние файлов, показывает изменения и помогает понять, кто, когда и почему изменил код. При работе с конфигурацией безопасности это особенно важно.

✎Рабочая папкаИзменили файлы

▣Staging areaВыбрали изменения
git commit
◇ИсторияСоздан коммит

☁RemoteОтправили изменения
Безопасный рабочий процесс bash
git init                        # новый репозиторий
git status                      # проверить изменения
git add src/main.py .gitignore   # добавлять нужные файлы явно
git diff --cached               # проверить, что попадёт в коммит
git commit -m "Add safe configuration"
git log --oneline               # история

git diff HEAD~1                 # изменения относительно прошлого коммита
git blame src/main.py           # кто изменял строки
git revert <commit_hash>         # новый коммит, отменяющий указанный
Интерактивный симулятор Git

Выполните шаги в порядке. Состояние отображается ниже; реальные команды на компьютере не запускаются.

Working: чисто
Staged: пусто
Commits: 0
Сначала измените файл.
Осторожно: git reset --hard способен уничтожить незакоммиченные изменения. Для отмены опубликованного коммита обычно безопаснее git revert, сохраняющий историю.

Тренажёр 01

Определить, опубликован ли секретный ключ

Программа получает строковую переменную api_key. Считайте строку через input() без приглашения. Если строка не пустая и не равна строке NONE, выведите SECRET_FOUND. Иначе — OK.

Алгоритм

  1. Прочитать строку с клавиатуры.
  2. Проверить одновременно api_key (непустое значение) и api_key != "NONE".
  3. Напечатать строго одно из двух сообщений.
Пример входа
sk_live_123456
Пример выхода
SECRET_FOUND
Решение и пояснение ⌄
Тренажёр 1 — готовый ответ python
api_key = input()
if api_key and api_key != "NONE":
    print("SECRET_FOUND")
else:
    print("OK")

Пустая строка в Python оценивается как False. Выражение с and истинно, только когда строка непустая и не равна NONE. Чувствительность к регистру важна: None и NONE — разные строки.

Проверить тесты

Граничные случаи

О модели угроз: наличие строки ещё не доказывает реальную утечку. Это учебный классификатор; настоящий ключ нельзя вводить в онлайн-формы.
Тренажёр 02

Определить правило .gitignore по имени файла

На вход подаётся имя файла filename. Если строка оканчивается на .env, .key или .log, вывести IGNORE, иначе TRACK. Регистр букв учитывается.

Алгоритм

  1. Прочитать имя файла через input() без подсказки.
  2. Проверить конец строки методом endswith().
  3. Вывести IGNORE для перечисленных окончаний.
  4. Во всех других случаях вывести TRACK.
Пример входа
.env
Пример выхода
IGNORE
Решение и пояснение ⌄
Тренажёр 2 — готовый ответ python
filename = input()
ends = (".env", ".key", ".log")
if filename.endswith(ends):
    print("IGNORE")
else:
    print("TRACK")

str.endswith() принимает кортеж окончаний. Это проще, чем составлять три сравнения через or. Отметьте разницу между этой учебной проверкой и реальными glob-шаблонами .gitignore.

Проверка режима отладки

Переменная debug_mode управляет отображением диагностических сообщений. Перед обычным запуском приложения отладку рекомендуется отключать.

Условие и алгоритм

  1. Исходное значение: debug_mode = True.
  2. Если debug_mode истинно, вывести «Внимание: режим отладки включён».
  3. Иначе вывести «Безопасный режим работы».
  4. Используйте условный оператор if / else.

Маскирование токена доступа

Дан строковый токен. Требуется узнать его длину и вывести маску: все символы, кроме последних четырёх, заменить символами *.

Условие и алгоритм

  1. Определите длину токена через len().
  2. Сформируйте строку звёздочек и добавьте последние 4 символа через срез [-4:].
  3. Выведите длину и маскированную строку.
  4. Для коротких токенов (до 4 символов) безопаснее скрывать их целиком.
Ожидаемый результат
15
***********Pq41

Проверьте также токены длиной 0, 3 и 4 символа.

Показать готовое решение и подробный разбор⌄
Решение задания 2 python
api_token = "sk-8f92kLm7Pq41"  # только учебный пример
n = len(api_token)
mask = "*" * n if n <= 4 else "*" * (n - 4) + api_token[-4:]
print(n)
print(mask)

Построчный разбор

  1. len(api_token) даёт длину исходного токена.
  2. Умножение строки "*" на число создаёт нужное количество символов.
  3. Срез [-4:] берёт последние четыре символа.
  4. Для коротких значений полное скрытие защищает от случайного показа всего токена.
Маскирование экрана не заменяет защиту в логах, сетевых запросах и хранилище.

Получение секрета из переменной окружения

Секрет нельзя держать в исходниках. Программа должна найти API_TOKEN среди переменных окружения и сообщить только статус загрузки.

Условие и алгоритм

  1. Предварительно установите переменную окружения API_TOKEN (вне Python-программы).
  2. Получите значение через os.getenv("API_TOKEN").
  3. Если значение существует и непустое, выведите «API_TOKEN загружен».
  4. Иначе выведите «Ошибка: API_TOKEN не найден». Сам токен не печатайте.
Ожидаемый результат
API_TOKEN загружен
# или: Ошибка: API_TOKEN не найден

Для локального теста можно использовать python-dotenv и файл .env.

Показать готовое решение и подробный разбор⌄
Решение задания 3 python
import os

api_token = os.getenv("API_TOKEN")
if api_token:
    print("API_TOKEN загружен")
else:
    print("Ошибка: API_TOKEN не найден")

Построчный разбор

  1. Импорт os открывает доступ к окружению процесса.
  2. os.getenv() возвращает None, если имя отсутствует.
  3. Пустая строка тоже считается ложным условием.
  4. Программа сообщает статус, но не раскрывает значение секрета.
Присваивание API_TOKEN = "..." в ячейке Jupyter не создаёт переменную окружения. Это частая ошибка в исходных примерах.

Поиск чувствительных файлов

В проекте задан список файлов. Нужно вывести предупреждение только для файлов, которые есть в списке опасных имён.

Условие и алгоритм

  1. Создайте список files из условия.
  2. Создайте список dangerous_files = [".env", "secret.key", "passwords.txt"].
  3. Переберите files с помощью for.
  4. Для каждого совпадения выведите «Не добавлять в Git: имя_файла».
Ожидаемый результат
Не добавлять в Git: .env
Не добавлять в Git: secret.key
Не добавлять в Git: passwords.txt

В настоящих проектах проверяйте не только имена, но и содержимое и пути.

Показать готовое решение и подробный разбор⌄
Решение задания 4 python
files = [
    "main.py", "README.md", ".env", "config.py",
    "secret.key", "passwords.txt", "app.py"
]
dangerous_files = [".env", "secret.key", "passwords.txt"]

for filename in files:
    if filename in dangerous_files:
        print("Не добавлять в Git:", filename)

Построчный разбор

  1. files — список всех файлов проекта.
  2. dangerous_files — перечень значений, которые точно нужно исключить для этой задачи.
  3. Оператор in проверяет принадлежность списку.
  4. print вызывается только для найденных совпадений.
Это учебный список, а не полноценный сканер секретов.

Проверка версий зависимостей

Список содержит записи о Python-библиотеках. В простом учебном формате запись с == означает зафиксированную версию. Найдите записи без ==.

Условие и алгоритм

  1. Создайте список dependencies из условия.
  2. Переберите элементы через цикл for.
  3. Если в строке нет подстроки ==, выведите «Версия не указана: ...».
  4. Не изменяйте исходные записи.
Ожидаемый результат
Версия не указана: flask
Версия не указана: pytest

Проверьте замены имён библиотек в списке.

Показать готовое решение и подробный разбор⌄
Решение задания 5 python
dependencies = [
    "requests==2.32.3",
    "flask",
    "python-dotenv==1.0.1",
    "pytest"
]

for dependency in dependencies:
    if "==" not in dependency:
        print("Версия не указана:", dependency)

Построчный разбор

  1. Цикл проверяет зависимости по очереди.
  2. Условие "==" not in dependency истинно для строки без двойного знака равенства.
  3. Поэтому для flask и pytest выводится предупреждение.
Реальные спецификаторы Python сложнее: >=, ~=, ограничения среды, URL и др. Отсутствие == не всегда означает ошибку безопасности.

Проверка безопасной настройки проекта

Состояние проекта описано четырьмя флагами. Требуется написать проверку, подтверждающую, что все обязательные меры выполнены.

Условие и алгоритм

  1. venv_created — окружение создано.
  2. env_configured — переменные окружения настроены.
  3. gitignore_exists — существует .gitignore.
  4. secrets_in_code — обнаружены секреты в исходниках; безопасное значение False.
  5. Объедините условия с and и выведите понятный статус.
Ожидаемый результат
Требуются дополнительные меры безопасности

Поменяйте gitignore_exists на True и проверьте смену результата.

Показать готовое решение и подробный разбор⌄
Решение задания 6 python
venv_created = True
env_configured = True
gitignore_exists = False
secrets_in_code = False

safe = (venv_created and env_configured
        and gitignore_exists and not secrets_in_code)

if safe:
    print("Безопасная настройка: OK")
else:
    print("Требуются дополнительные меры безопасности")

Построчный разбор

  1. Первые три флага должны быть True.
  2. Четвёртый флаг должен быть False, поэтому используется not.
  3. Оператор and требует истинности всех четырёх условий.
  4. В исходных данных .gitignore отсутствует — итоговая проверка не проходит.
Этот результат показывает соблюдение четырёх условий, а не полную безопасность продукта.

▣ Ситуация из практики

Перед публикацией учебного проекта в публичный репозиторий проверяем: не попали ли туда пароли, токены и локальные настройки.

Актив: Исходный код и токены. Угроза: Секрет попал в Git.

◉ Разбираем причинно-следственную связь

Файл .env сам по себе не обеспечивает безопасность. Нельзя коммитить файл с реальными секретами. Если токен уже опубликован, удалить файл недостаточно: ключ нужно отозвать и заменить.
