01

Как работает ООП

Объект объединяет данные и операции над ними. Это полезно, когда у каждой сессии, токена или счётчика должно быть собственное состояние.

Четыре строительных блока

classШаблон объекта, задающий его данные и поведение.
__init__(self, ...)Конструктор: создаёт начальное состояние экземпляра.
selfСсылка на конкретный объект внутри его методов.
Инкапсуляция: внешний код вызывает методы add_event(), status(), get_count(), а изменение внутреннего счётчика происходит внутри объекта. В Python _secret — соглашение о защищённости, а __count — механизм переименования (name mangling), не криптографическая защита.

Сценарий на уровне алгоритма

Инициализация → событие → изменение атрибута → проверка условия → решение. Вместо свободно расположенных переменных и функций вся логика живёт в классе.

Пример метода действия

self.__events += 1 меняет состояние объекта.

Пример метода решения

return "ALERT" if self.__events >= 5 else "OK" считывает это состояние и возвращает вердикт.

Счётчик событий безопасности с порогом тревоги 5.

Ключевая идея

Состояние объекта изменяется через методы; внешнему коду достаточно интерфейса.

class SecurityCounter:
    def __init__(self):
        self.count = 0

    def add_event(self):
        self.count += 1

    def get_count(self):
        return self.count

    def is_alert(self):
        return "ALERT" if self.count >= 5 else "OK"

counter = SecurityCounter()
for _ in range(5):
    counter.add_event()
print(counter.get_count())
print(counter.is_alert())

5
ALERT
Разбор

Конструктор устанавливает нулевое состояние. Метод add_event() отвечает за изменение, get_count() возвращает число, is_alert() сравнивает его с порогом.

Проверь границу: При 4 событиях — OK; при 5 — ALERT.

        self._secret = secret

    def mask_secret(self):
        if len(self._secret) <= 2:
            return "**"
        return self._secret[:2] + "*" * (len(self._secret) - 2)

    def reveal_secret(self, is_admin):
        if is_admin:
            return self._secret
        return "Доступ запрещён"

Разбор типичных ошибок

① Забыли self

Метод экземпляра должен принимать self первым аргументом. При вызове obj.add() Python подставляет ссылку на obj автоматически.

② Перепутали < и <=

«Меньше трёх» — это строго < 3. При значении 3 уже выполняется ветка блокировки. В заданиях 5 и 17 диапазон от 3 до 5 включительно.

③ Смешали строку и булево значение

"True" — строка, а True — логическое значение. Для флагов MFA и шифрования используется именно True/False.

④ Приняли соглашения Python за полноценную защиту

Запись _secret сигнализирует разработчикам, что атрибут внутренний, но не запрещает доступ к нему на уровне языка. Для реальной защиты нужны проверка полномочий на сервере, хеширование паролей, криптографические протоколы и безопасное хранение секретов.

⑤ Добавили лишнюю проверку

Класс Token из самопроверки № 2 должен проверять только минуты, а TemporaryAccess из задачи № 9 — и непустое имя, и минуты. Даже похожие классы имеют разные требования.
