Модуль 01 · Теория

Не всякая случайность безопасна

Одинаково «случайный» на вид результат может быть принципиально разным по защищённости. Для криптографии важен не внешний вид строки, а её непредсказуемость.

PRNG · генератор псевдослучайных чисел

Предсказуемая цепочка

Программа детерминированно вычисляет очередное значение из своего состояния.

Python · random
import random

rng = random.Random(42)
print(rng.random())
print(rng.random())
# Одинаковый seed → одинаковая последовательность
  • Подходит для симуляций, игр и экспериментов.
  • Повторяемость полезна для тестирования.
  • Не предназначен для секретных токенов.
→
CSPRNG · криптографически стойкий генератор

Сложно предсказать

Алгоритм проектируют так, чтобы наблюдение выходных данных не позволяло практически вычислить будущие значения.

Python · secrets
import secrets

token = secrets.token_hex(16)
print(token)
# Токен из 16 случайных байт
  • Подходит для токенов, паролей и ключевого материала при правильном применении.
  • Использует надёжный источник ОС.
  • Не предусматривает пользовательский seed.
Важное уточнение: PRNG — общее название псевдослучайных генераторов. CSPRNG — их криптографически стойкий класс. Поэтому противопоставление здесь означает обычный random.Random и криптографический источник, а не «PRNG против любого CSPRNG».

Энтропия

Мера неопределённости

В контексте теста верный ответ — непредсказуемость. Строго говоря, энтропия измеряет неопределённость распределения значений. Для анализа стойкости секретов важна в том числе минимальная энтропия.

Hmin = −log₂(pmax)pmax — вероятность наиболее вероятного значения

Если 16 байт получены независимо и равномерно случайно, пространство равно 2128 значений. Само число байт без качественного источника случайности не гарантирует 128 бит энтропии.

#
Байты ≠ символы

16 байт, 128 бит, 32 hex-символа

Один байт — 8 бит. Поэтому secrets.token_bytes(16) возвращает ровно 16 байт. А token_hex(16) кодирует те же 16 байт в 32 печатных символа (по два на байт).

16 × 8 = 128 бит16 байт → 32 символа в hexadecimal
0xA90x3F0xC8...16 байт

Число символов зависит от кодирования: hex и URL-safe Base64 представляют случайные байты по-разному.

01

Чем отличается криптографически стойкий генератор (CSPRNG) от обычного PRNG?

Верно: непредсказуемость. Важна практическая невозможность предсказать выход по наблюдениям. У CSPRNG тоже есть внутреннее состояние/инициализация; «нет seed» не определяющий признак.
02

Какой модуль Python следует использовать для генерации криптографически стойких случайных чисел?

Верно: secrets. Он специально предназначен для безопасных токенов и секретов. Обычный random не годится; math.random вообще не является стандартной функцией Python.
03

Что такое «энтропия» в контексте криптографии?

Верно: непредсказуемость — лучший вариант из предложенных. Более точно энтропия количественно характеризует неопределённость; она не равна длине ключа или числу раундов AES.
04

Почему функция random.random() небезопасна для токенов?

Верно: предсказуема. Mersenne Twister детерминирован и не создавался для защиты секретов. Его скорость и диапазон возвращаемых значений не объясняют криптографическую уязвимость.
05

Сколько байт возвращает функция secrets.token_bytes(16)?

Верно: 16 байт. Параметр nbytes задаёт число байт. Это 128 бит, если умножить на 8. В token_hex(16) получится 32 шестнадцатеричных символа.

Модуль 03 · Тренажёр Python 01

Анализ суммы кодов символов

Повторяем input(), цикл for, встроенную функцию ord(), оператор % и условную конструкцию if.

01

Условие задачи

Считайте строку message через input() без приглашения. Вычислите сумму кодов Unicode всех её символов. Если сумма чётная — выведите EVEN, иначе — ODD.

  • Проверяется использование ord() и накопление суммы в цикле.
  • Вывод должен быть строго одним словом, без дополнительных сообщений.

Как работает ord()

Каждый символ соответствует числовой кодовой точке. Для ABC программа получает:

A → 65B → 66C → 67198EVEN
  1. Читаем строку: message = input().
  2. Создаём счётчик: total = 0.
  3. Для каждого символа выполняем total += ord(char).
  4. Проверяем остаток total % 2. Ноль означает чётное число.
  5. Печатаем строго EVEN или ODD.

Не путайте: ord() возвращает кодовую точку Unicode, а не количество байт в UTF-8. Например, русские буквы обычно занимают в UTF-8 больше одного байта.

Посмотреть полное решение на Python

Рабочий вариант без лишних приглашений и вспомогательного вывода — подходит для автоматической проверки:

solution_1.py · готовый ответ
message = input()
total = 0

for char in message:
    total += ord(char)

if total % 2 == 0:
    print("EVEN")
else:
    print("ODD")
Сложность: O(n) по времени, O(1) дополнительной памяти при подсчёте суммы.

Короткая альтернатива: результат можно записать и через sum(ord(char) for char in message), но исходное задание проверяет и самостоятельное построение цикла.

Модуль 04 · Тренажёр Python 02

Выбор лучшего токена

Сортировка не нужна: достаточно пройти по строкам и хранить текущего лидера. Разбираем множества set, длину len и многоуровневые критерии.

02

Условие задачи

Считайте целое число n, затем n токенов — по одному в строке. Выведите один «лучший» токен, определяя победителя по строгому приоритету:

  • 1. Максимум уникальных символов — len(set(token)).
  • 2. При равенстве — максимальная длина токена.
  • 3. При полном равенстве — первый во входном порядке.
Критерий 1 → уникальные символы

"aabbc" → set(...) даёт {'a', 'b', 'c'}; всего 3 уникальных символа. Повторение символа не увеличивает показатель.

Критерий 2 → длина, затем порядок

"abc" и "abcc" имеют по 3 уникальных символа, но побеждает второй как более длинный. При равной длине сохраняется предыдущий лидер.

Интерактивная проверка

Список входных токенов

Каждая строка — отдельный токен. Число n определяется по количеству строк. Чтобы сохранить токен с пробелами, не удаляйте их.

n = 4

Симуляция алгоритма на JavaScript, не выполнение произвольного Python-кода. Результат определяется теми же правилами выбора.

Как менялся лидер

Посмотреть полное решение на Python

При сравнении учитываем первый и второй критерий. При полном равенстве обновление не происходит: так сохраняется первый встретившийся кандидат.

solution_2.py · готовый ответ
n = int(input())
best = ""
best_unique = -1

for _ in range(n):
    token = input()
    unique_count = len(set(token))

    if (unique_count > best_unique or
        (unique_count == best_unique and len(token) > len(best))):
        best = token
        best_unique = unique_count

print(best)
Суммарно O(L) по времени при обычных операциях с множествами, где L — сумма длин всех токенов; дополнительная память — O(M), где M — максимальное число уникальных символов одного токена, не считая входного токена и лидера.

Почему best_unique = -1? Даже пустой токен имеет 0 уникальных символов, а 0 больше −1. Первый токен обязательно станет кандидатом. Почему нет >= при сравнении длины? Тогда новый токен вытеснит ранний при полном равенстве — это нарушит условие.

Принципиальный нюанс информационной безопасности: критерии этого тренажёра — учебные и не оценивают настоящую криптографическую стойкость. Токен с большим количеством уникальных символов может быть полностью предсказуем. Для создания секретов используйте secrets, а не подбор по внешнему разнообразию.

Три правила

Запомните

  1. Для секретов — secrets. Не создавайте токены с обычным random.
  2. Энтропия зависит от распределения. Длина и «красивый» вид секретной строки — не гарантия безопасности.

Вопросы, которые часто возникают

Может ли CSPRNG быть псевдослучайным?

Да. Обычно CSPRNG — именно криптографически стойкий псевдослучайный генератор, состояние которого инициализируется непредсказуемыми данными. Псевдослучайность сама по себе не делает алгоритм небезопасным.

Чем 16 байт отличаются от 16 hex-символов?

16 байт — 128 бит сырого двоичного значения. 16 hex-символов кодируют только 8 байт (64 бита), потому что каждый hex-символ содержит 4 бита. token_hex(16) даёт 32 hex-символа.

Почему множество set() убирает повторы?

Множество хранит уникальные элементы. Например, set("aabbc") содержит только a, b, c. Порядок элементов самого множества не нужен: нас интересует только его размер.

Можно ли измерить безопасность токена числом разных символов?

Нет. Один и тот же набор символов может быть создан как криптографически стойким генератором, так и полностью предсказуемым правилом. Настоящая защищённость зависит прежде всего от генерации, распределения и числа потенциальных вариантов, а не от внешнего вида.
