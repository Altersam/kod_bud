list, dict, set, tuple: четыре разных инструмента

Структуру выбирают по операции, которая наиболее важна: сохранять порядок, искать по ключу, исключать дубликаты или фиксировать неизменяемую последовательность.

* Для `dict` и `set` оценка O(1) — средняя, при нормальном распределении хешей. Худший случай может быть O(n). Изменяемые объекты, например обычный `list`, не могут служить элементами `set` или ключами `dict`.

Частая ошибка: запись «list O(n)» не означает, что каждая операция со списком медленная. `list[i]` и `len(list)` — O(1), а `x in list` — O(n). Аналогично `tuple` не имеет универсальной сложности O(1): индексирование O(1), поиск элемента O(n).

03

Алгоритмическая сложность: O(n) против O(1)

Big O описывает, как число операций растёт вместе с размером входных данных. Это не число секунд и не гарантия конкретного времени на вашем компьютере.

O(n)

Линейный поиск в list

Для отсутствующего элемента список нужно просмотреть целиком. При удвоении списка количество сравнений тоже примерно удваивается.

O(1) в среднем

Поиск в set

Хеш помогает перейти в нужную область таблицы без последовательного просмотра всех элементов. Но предварительное построение set стоит O(n).

04

Что внутри set и dict: хеш-таблица

Хеш-функция вычисляет числовой отпечаток ключа. По нему структура определяет, где искать запись. Столкновение ключей в одной области называется коллизией.

ВИЗУАЛИЗАЦИЯ

Восемь условных корзин хеш-таблицы

Введите строку и добавьте её или найдите. Схема использует специально упрощённую хеш-функцию для обучения: реальная реализация CPython устроена иначе, а строковый хеш Python может зависеть от случайного зерна процесса.

Каждый ключ отображается в одну из восьми условных корзин.

Почему поиск обычно быстрый?

Вместо проверки каждого из n элементов хеш-таблица сразу обращается к вычисленной позиции. При редких коллизиях длина последующего поиска мала.

Почему O(1) не абсолютное?

Коллизии, перераспределение таблицы и затраты на вычисление хеша влияют на реальную стоимость. Память и тип ключа также имеют значение.

Rate limiting: защита от слишком частых запросов

Для каждого клиента можно хранить временные метки запросов. В скользящем окне устаревшие метки удаляются, а при достижении лимита следующий запрос отклоняется.

История запросов появится здесь.

Почему не просто list?

Списковое выражение, которое каждый раз проходит по всем временным меткам, тратит O(k) на фильтрацию каждого запроса. `deque.popleft()` позволяет быстро удалить метки с начала очереди.

Сложность корректной реализации

При `deque` обработка одного вызова зависит от числа удаляемых просроченных меток; каждую метку добавляют и удаляют не более одного раза. Для ограниченного числа принятых запросов это эффективно, но не универсальное O(1) в худшем случае.

Инженерное замечание: для нескольких серверов нужно общее состояние (например, Redis), правильный источник времени и политика очистки неактивных клиентов. Для попыток входа лимит только по IP недостаточен: учитывают учётную запись, устройство, контекст и риск распределённой атаки.

Устойчивость к перебору: от числа комбинаций к защите

Полный перебор — это проверка вариантов из некоторого пространства. Важны не только количество комбинаций, но и модель угроз: онлайн-попытки входа и офлайн-проверки утёкших хешей принципиально различаются.

Хеширование паролей

Быстрые хеш-функции вроде MD5 и простого SHA-256 не подходят для хранения паролей. Для этого применяют специализированные алгоритмы Argon2id, scrypt или PBKDF2 с индивидуальной солью и подходящими параметрами.

Проверка скомпрометированных паролей

Have I Been Pwned предлагает API k-anonymity: клиент локально хеширует пароль и отправляет только префикс SHA-1, а сравнение суффикса делает у себя. Не нужно загружать огромную базу хешей в один Python-set.

Нет универсальных «секунд взлома»: время зависит от распределения реально выбранных паролей, параметров KDF, оборудования, скорости ограничителя и наличия MFA. Пространство комбинаций само по себе не даёт достоверного прогноза времени атаки. Не следует использовать учебные сравнения для оценки защищённости реальных аккаунтов.
08

Стандартная библиотека: инструменты для обработки данных

Важные встроенные модули позволяют считать события, работать с IP/CIDR, сравнивать подписи и анализировать бинарные форматы без сторонних зависимостей.

Не смешивать понятия: `hmac` — аутентичность сообщений, `hashlib` — хеш-функции и некоторые KDF, `ipaddress` — адреса/сети, `collections` — структуры для подсчёта и очередей. Ни один из этих модулей сам по себе не заменяет полноценную систему безопасности.

◉ Разбираем причинно-следственную связь

Словарь хранит соответствие «ключ → значение», а Counter сокращает запись частотного подсчёта. Множество удобно для быстрой проверки принадлежности, но не хранит количество повторений.

Что проверяем: Сравнить частоты, не только итоговое число.

⌘ Python · фрагмент для самостоятельной проверки

from collections import Counter
failed_ips = ["10.0.0.2", "10.0.0.3", "10.0.0.2", "10.0.0.2"]
counts = Counter(failed_ips)
print(counts["10.0.0.2"])
print(sorted(counts.items()))
Ожидаемый результат: 3 [('10.0.0.2', 3), ('10.0.0.3', 1)]

Код запускается в Python 3 и использует только стандартную библиотеку. Эксперименты выполняйте на учебных данных и в разрешённом окружении.
