TTL и revoke

«revoke — отправить заново / пересоздать»

TTL = Time To Live — срок жизни. revoke() — немедленно отозвать уже выданный токен. Повторная выдача — отдельная операция.

Модели без «кубиков»

Три рабочие аналогии, которые не ломают смысл ООП

Объект = запись состояния + допустимые операции

Не «кубик», а скорее банковский счёт в системе: у него есть состояние (owner, balance) и набор разрешённых операций (deposit, withdraw).

Метод не просто «функция рядом»: он работает с состоянием конкретного экземпляра через self.

Инкапсуляция = транзакционный шлюз

Клиент банка не имеет SQL-доступа и не пишет balance = 1_000_000. Он отправляет команду «перевести 500».

Шлюз проверяет права, сумму, лимиты, журналирует операцию — и только затем изменяет состояние.

Полиморфизм = единая точка аутентификации

Система вызывает authenticate(), не зная деталей:

PasswordAuthTokenAuthCertificateAuth

Интерфейс одинаковый, реализация проверки различается.

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        if amount > 0:
            self.balance += amount
            return "Деньги зачислены"
        return "Сумма должна быть больше нуля"

    def withdraw(self, amount):
        if amount <= 0:
            return "Сумма должна быть больше нуля"
        if amount > self.balance:
            return "Недостаточно средств"
        self.balance -= amount
        return "Деньги сняты"

Инкапсуляция

Контролируем изменение, а не просто «прячем» данные

Точная формулировка: объект поддерживает свои инварианты — условия, которые всегда должны оставаться истинными. Например, баланс нельзя сделать отрицательным произвольным присваиванием. Внешний код просит объект выполнить операцию, а объект сам решает, допустима ли она.

Открытый атрибут

self.balance = balance

account.balance = -999999 проходит без проверки.

Внутренний атрибут

self.__balance = balance

Изменение переводится в методы с проверкой.

Наследование

Специализация: наследник «является» родителем

Проверка IS‑A: SecurityAnalyst является Employee — хорошее наследование. «Квартира является домом» — нет, это уже отношение HAS‑A/часть‑целое, а не наследование.
class Employee:
    def __init__(self, name, position):
        self.name = name
        self.position = position

    def describe(self):
        return f"{self.name}: {self.position}"

class SecurityAnalyst(Employee):
    def __init__(self, name, level):
        super().__init__(name, "Аналитик ИБ")
        self.level = level

    def analyze_incident(self):
        return f"{self.name} анализирует инцидент уровня {self.level}"

analyst = SecurityAnalyst("Мария", "High")

Что происходит

SecurityAnalyst(Employee) получает поведение базового класса и добавляет своё.

ИБ-нюанс: наследник может нарушить инварианты родителя. Чувствительные правила лучше контролировать методами.

Схема полиморфизма

Внешний код не обязан знать точный класс объекта. Он знает контракт: «у объекта есть метод move()».
Уровни доступа

Python: соглашения, а не строгие модификаторы

Не Java/C++: в Python нет настоящего ключевого слова private. _name — соглашение, __name — name mangling. Код, который уже выполняется внутри процесса Python, технически может добраться до этих данных.
public_attrОбычный атрибут, доступен всем.
_protected_attrСоглашение: «внутренний, не трогать без необходимости».
__private_attrВключает name mangling.
Важно: двойное подчёркивание не шифрует данные и не создаёт абсолютную приватность.
6

Как Python хранит «приватное» имя

Поэтому __attr — это механизм дисциплины и защиты от случайного доступа, а не средство шифрования.
Name mangling

__attr → _ClassName__attr

class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):
        return self.__balance

account = BankAccount(1000.0)

print(account.get_balance())

# account.__balance -> AttributeError
# account._BankAccount__balance -> технически возможно,
# но нарушает контракт класса

Визуализатор имени

account.__balance = 5000

Снаружи это не изменяет внутренний _BankAccount__balance. Обычно создаётся другой атрибут с буквальным именем __balance.

account._BankAccount__balance

Так технически можно обратиться к mangled-имени. Поэтому двойное подчёркивание — не секретность, а защита от случайного конфликта и сигнал «не трогать».

Менеджер паролей

Пароль не шифруем и не «разблокируем» — проверяем производное значение

Правильная модель: пароль + соль + параметры KDF → производное значение. При входе вычисление повторяется. Если результаты совпали — пароль верный. Обратной операции «получить пароль из хэша» в нормальной схеме нет.

Небезопасно

  • Публичный хэш.
  • Фиксированная соль.
  • MD5 — слишком быстрый и устаревший для паролей.
  • Хэш можно заменить напрямую.
password_hash = ""
salt = "fixed_salt"
hashlib.md5(...)
mgr.password_hash = "..."

Лучше

  • __password_hash и __salt скрыты от обычного API.
  • Соль случайная: os.urandom(32) возвращает 32 случайных байта, а не число от 0 до 31.
  • Используется KDF для паролей.
  • Проверка через verify().
  • __repr__ не раскрывает секреты.
import os
import hashlib
import hmac

class PasswordManager:
    def __init__(self, password):
        self.__salt = os.urandom(32)
        self.__password_hash = self.__hash(password)

    def __hash(self, password):
        return hashlib.pbkdf2_hmac(
            "sha256",
            password.encode(),
            self.__salt,
            100_000
        )

    def verify(self, password):
        candidate = self.__hash(password)
        return hmac.compare_digest(
            candidate,
            self.__password_hash
        )

    def __repr__(self):
        return "PasswordManager(<protected>)"

Симулятор verify()

Практика: в реальных проектах используют специализированные библиотеки и современные схемы вроде Argon2id/bcrypt/scrypt либо корректно настроенный PBKDF2.

Как должен идти пароль через систему

При проверке введённый пароль проходит тот же KDF с той же солью, а затем сравниваются результаты. Сам пароль не требуется хранить.

@property

Управляемый атрибут: выглядит как поле, работает как метод

class Profile:
    def __init__(self):
        self.__privilege_level = 0

    @property
    def privilege_level(self):
        return self.__privilege_level

    @privilege_level.setter
    def privilege_level(self, value):
        if not 0 <= value <= 3:
            raise ValueError("Диапазон: 0..3")

        print(f"[AUDIT] privilege_level -> {value}")
        self.__privilege_level = value

    @privilege_level.deleter
    def privilege_level(self):
        raise AttributeError("Удаление запрещено")
