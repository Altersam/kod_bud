01 / КЕЙС

Техническое задание

Команда создала учебный скрипт для генерации паролей и сохранения данных локально. Формально он выполняет задачу, но в реальном сервисе может раскрывать секреты и аварийно завершаться.

Ситуация

Что умеет прототип?

Получает название сервиса и логин, спрашивает длину, генерирует пароль из букв и цифр, записывает сервис;логин;пароль в passwords.txt и выводит все записи.

02 / КОД

Исходный скрипт

Точно воспроизведён кейс из задания. Код приведён для анализа и не рекомендуется к реальному использованию для хранения паролей.

legacy_passwords.py · исходный прототип
import random

PASSWORDS_FILE = "passwords.txt"

def generate_password(length):
    chars = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"
    password = ""
    for _ in range(length):
        password += random.choice(chars)
    return password

def save_password(service, login, password):
    with open(PASSWORDS_FILE, "a", encoding="utf-8") as f:
        f.write(service + ";" + login + ";" + password + "\n")

def load_passwords():
    with open(PASSWORDS_FILE, "r", encoding="utf-8") as f:
        return f.readlines()

service = input("Сервис: ")
login = input("Логин: ")
length = int(input("Длина пароля: "))
password = generate_password(length)
print("Сгенерированный пароль:", password)
save_password(service, login, password)
print(load_passwords())
⚠ Демонстрационный уязвимый код. Не сохраняйте в него настоящие учётные данные.
Генерация

random.choice()

Выбирает символы из строки. Выбор выглядит случайным, но модуль random не предназначен для криптографических секретов.

Сохранение

open(..., "a")

Дописывает строки к файлу без шифрования. Любой получивший доступ к содержимому файла прочитает пароли.

Чтение

readlines()

Читает весь файл в список строк. В конце исходного скрипта этот список полностью выводится на экран.

Пошаговый разбор работы исходного кода
  1. Переменная PASSWORDS_FILE задаёт относительный путь к файлу.
  2. generate_password(length) добавляет по символу в строку на каждой итерации цикла.
  3. save_password() открывает файл в режиме добавления a и пишет три значения через точку с запятой.
  4. load_passwords() возвращает список строк файла.
  5. int(input(...)) преобразует введённую длину без проверки корректности.
  6. print(...) раскрывает отдельный пароль и затем весь файл в консоли.
03 / АУДИТ

Девять проблем и оценка рисков

Выберите категорию, чтобы отфильтровать замечания. У каждой проблемы указаны источник, возможные последствия, серьёзность и способ исправления.

RISK 01 · SECURITYВЫСОКИЙ

Предсказуемая псевдослучайность

random.choice(chars) использует PRNG для моделирования, а не защищённый источник случайности.

Последствие: при раскрытии или восстановлении внутреннего состояния генератора могут стать предсказуемыми его результаты.

Решение: заменить на secrets.choice().

RISK 02 · SECURITYКРИТИЧЕСКИЙ

Пароли хранятся открытым текстом

f.write(... + password) записывает секреты в читаемый .txt.

Последствие: чтение файла, его резервной копии или синхронизированной копии раскрывает все сохранённые пароли.

Решение: не хранить пароль без необходимости; для менеджера паролей — защищённое хранилище и шифрование.

RISK 03 · SECURITYВЫСОКИЙ

Утечка через консоль

Два вызова print() показывают сгенерированный пароль и весь файл.

Последствие: доступ к истории терминала, трансляции экрана или журналу вывода раскрывает секреты.

Решение: выводить только по запросу в доверенной среде, исключить массовый вывод и логи секретов.

RISK 04 · INPUTВЫСОКИЙ

Нет проверки длины

int(input(...)) падает на abc; отрицательная длина даёт пустой пароль; чрезмерная длина расходует ресурсы.

Последствие: сбой, пустой или неудобный пароль.

Решение: try/except ValueError и пределы допустимой длины, например 12–128.

RISK 05 · INPUTСРЕДНИЙ

Разделитель ; и перевод строки

В полях service и login могут встретиться ; или \n. При дальнейшем разборе файла записи будут неоднозначными.

Последствие: повреждение структуры и подмена интерпретации отдельных полей.

Решение: структурированный формат/БД с безопасной сериализацией и валидацией входа.

RISK 06 · ARCHITECTUREСРЕДНИЙ

Жёсткий путь и относительное расположение

PASSWORDS_FILE = "passwords.txt" зависит от текущего каталога запуска.

Последствие: запись не туда, куда ожидали; проблемы прав, резервного копирования и настройки окружения.

Решение: конфигурируемый путь к защищённому хранилищу; не класть секреты рядом с исходниками.

RISK 07 · ARCHITECTUREСРЕДНИЙ

Нет обработки ошибок файловой системы

Ошибки доступа, нехватка места или повреждённый файл не обрабатываются. load_passwords() отдельно упадёт при отсутствии файла.

Последствие: потеря доступности или некорректное поведение.

Решение: обработка OSError, контроль целостности, атомарные операции и тесты.

RISK 08 · ARCHITECTUREСРЕДНИЙ

Неуправляемый файл записей

Режим "a" постоянно добавляет данные: нет уникальных ключей, обновления, удаления, контроля дубликатов или доступа.

Последствие: трудности сопровождения и рост рисков при расширении сервиса.

Решение: выделить отдельный слой хранилища с операциями создания, обновления и удаления.

RISK 09 · QUALITYНИЗКИЙ

Слабая читаемость и тестируемость

Конкатенация строк вместо join()/f-строк, отсутствие аннотаций и документации функций, бизнес-логика смешана с вводом/выводом.

Последствие: изменения и тестирование требуют больше времени; повышается вероятность ошибок.

Решение: понятные имена, функции с единственной ответственностью, типы, тесты и PEP 8.

Критичность указана для сценария внутреннего сервиса с реальными учётными данными. В учебной изолированной среде последствия могут быть ниже. Приоритизация зависит от модели угроз.

Готовые ответы на шесть вопросов кейса
  1. Какие слабые места? random, открытое хранение и вывод секретов, некорректный ввод, неоднозначная структура файла, отсутствие обработки ошибок, неудобная архитектура.
  2. Безопасна ли генерация? Нет, для секретов нужен secrets. Сам алфавит из 62 символов не делает длинный пароль заведомо слабым, но качество случайного выбора принципиально.
  3. Допустимо ли хранение? Не для реальных паролей. Для проверки паролей пользователей нужны адаптивные хэши; для менеджера, который должен вернуть пароль, — шифрованное хранилище.
  4. Какие сбои? ValueError при вводе нечисловой длины; пустой результат при отрицательной длине; проблемы с разделителем и переносами строк; ошибки диска/доступа.
  5. Что помешает расширению? Смешение логики и интерфейса, файловое хранилище без схемы данных, жёсткий путь и отсутствие тестов.
  6. Что исправить сначала? Исключить хранение и массовый вывод секретов, перейти на secrets, проверить ввод, затем выбрать защищённое хранилище и добавить обработку ошибок.
04 / УЛУЧШЕНИЯ

Как сделать безопаснее

Предлагаем два осмысленных уровня решения: простой генератор, который ничего не сохраняет, и сервис с защищённым хранилищем. Они решают разные задачи.

Вывести весь файлповторное раскрытие паролей

Вариант A · Минимальный безопасный генератор

Только стандартная библиотека Python. Генерирует пароль, проверяет длину, не пишет его в файл и не повторяет содержимое хранилища. Сам вывод нового пароля нужен пользователю, но должен происходить в доверенной среде.

secure_generator.py
import secrets
import string

ALPHABET = string.ascii_letters + string.digits + "!@#$%*-_"


def generate_password(length: int = 16) -> str:
    """Создать пароль с криптографически стойким выбором символов."""
    if not 12 <= length <= 128:
        raise ValueError("Длина должна быть от 12 до 128")
    return "".join(secrets.choice(ALPHABET) for _ in range(length))


if __name__ == "__main__":
    try:
        length = int(input("Длина пароля: ").strip())
        # Показываем новый пароль только в доверенной среде.
        print("Пароль:", generate_password(length))
    except ValueError as error:
        print("Ошибка:", error)
✓ Без сторонних библиотек. Длина 12–128 — учебное ограничение; для новых паролей обычно практичнее выбирать 16+ символов, если сервис поддерживает.
DIFF 01

Безопасный выбор

secrets.choice() использует криптографически стойкий источник случайности ОС.

DIFF 02

Строковая сборка

"".join(...) собирает символы без последовательной конкатенации.

DIFF 03

Проверка ошибок

try/except и диапазон длины не дают некорректному вводу остановить программу traceback-ом.

Вариант B · Если хранение действительно необходимо

Учебный пример интеграции с системным хранилищем учётных данных. Требуется установка pip install keyring, поддерживаемый безопасный backend и подходящие права ОС. Не рекомендуется для общего компьютера без отдельных пользовательских профилей.

secure_store_example.py · фрагмент
# Установка: pip install keyring
import keyring


def save_password(service: str, login: str, password: str) -> None:
    if not service.strip() or not login.strip():
        raise ValueError("Сервис и логин обязательны")
    # Используется backend keyring, настроенный в системе.
    keyring.set_password(service, login, password)


def load_password(service: str, login: str) -> str | None:
    # Доступ к секрету зависит от защиты ОС и backend.
    return keyring.get_password(service, login)


# Перед использованием проверьте backend и правила доступа.
# Не выводите сохранённые секреты в логи или общий терминал.
Важно: пакет keyring сам по себе не гарантирует безопасность любого backend — проверьте, что выбран защищённый системный механизм, а не небезопасное файловое хранилище.
Хэширование ≠ шифрование. Если система только проверяет пароль при входе, храните адаптивный хэш с солью (например, Argon2id). Если система должна восстановить сам пароль, как менеджер паролей, одностороннего хэша недостаточно: нужно надёжное шифрование, защита ключей и контроль доступа.
СЦЕНАРИЙ А · АУТЕНТИФИКАЦИЯ
Пароль → Argon2id + соль → хэшПри входе сравнивается результат проверки; исходный пароль не восстанавливается. Не использовать быстрый SHA-256 без специализированной password-KDF.
СЦЕНАРИЙ Б · МЕНЕДЖЕР ПАРОЛЕЙ
Пароль → шифрование → защищённое хранилищеДля получения пароля требуется ключ. Нужно защищать ключ, использовать аутентифицированное шифрование и модель прав доступа.
Приоритетный план изменений для команды
  1. P0: прекратить небезопасное хранение и массовый вывод секретов; ограничить доступ к уже созданному файлу и считать скомпрометированные пароли требующими смены.
  2. P0: заменить random на secrets.
  3. P1: ввести строгие проверки пользовательского ввода, обработку ошибок, безопасный формат данных.
  4. P1: определить, требуется ли вообще хранение, и выбрать соответствующий класс хранилища.
  5. P2: отделить генерацию, пользовательский интерфейс и хранилище, добавить тесты, управление версиями схемы и аудит доступа без записи секретов.
05 / ПРАКТИКА

Задание 1. Множество символов

Условие: дана строка password. Создайте множество всех её символов. Вычислите произведение длины строки и количества различных символов. Выведите целое число.

Пример

Ввод: abcabc

Вывод: 18

6 символов × 3 различных символа = 18.

Что проверяется

Работа со строкой и множеством set; понимание уникальности элементов; применение алгоритма ровно по условию.

Интерактивный тренажёр · вводите любую строку
Повторные символы показаны приглушённым цветом. Для каждого символа учитывается его Unicode-кодовая точка, как при обходе строки в Python.
6
Длина строки · L
3
Различных символов · U
18
Результат · L × U
6 × 3 = 18
Бирюзовые — первое появление символа; серые — повторения.
Точность терминов: в условии это названо «упрощённой энтропией», но len(password) * len(set(password)) не вычисляет энтропию пароля в битах и не является надёжной оценкой его взломостойкости. Это учебная метрика длины и разнообразия. Реальная оценка зависит от способа выбора пароля и модели атакующего.

Алгоритм решения

ШАГ 01

input()

Считываем введённую строку целиком, включая повторяющиеся символы.

ШАГ 02

set(password)

Создаём множество: каждый различный символ встречается в нём ровно один раз.

ШАГ 03

len() * len()

Находим оба количества и умножаем. Результат выводим print().

Посмотреть готовое решение на Python
task_1.py · решение
password = input()
unique_chars = set(password)
result = len(password) * len(unique_chars)
print(result)

Почему это работает: множество удаляет повторы. Для abcabc оно содержит a, b, c. Длина исходной строки — 6, множества — 3.

Сложность в среднем O(n) по времени и до O(k) по памяти, где n — длина строки, k — число различных символов.

Короткий вариант в одну строку
task_1_short.py
s = input()
print(len(s) * len(set(s)))

Чем учебная метрика отличается от энтропии в битах?

Для пароля длины L, составленного независимым равновероятным выбором из алфавита размера N, число возможных строк — N^L, а теоретическая неопределённость — H = L · log₂(N) бит. Например, для 16 независимых выборов из 62 символов это примерно 95,3 бита. Для человеческих паролей такую оценку нельзя применять автоматически: пользователи выбирают символы неравновероятно.

Метрика из задачи L × U считает фактически встреченные уникальные символы, а не пространство возможных независимых случайных выборов.

Задание 2. Коды символов

Условие: на вход программе подаётся строка. Для каждого символа найдите его числовой код с помощью ord() и выведите коды в одну строку через пробел, сохраняя порядок.

Пример

Ввод: AB

Вывод: 65 66

Заглавная латинская A — 65, B — 66.

Важно запомнить

ord() возвращает кодовую точку Unicode. Для латинских букв она совпадает со значением ASCII, но для кириллицы и эмодзи выходят другие числа.

ШАГ 03

Напечатать коды

ord(char) возвращает целое число; print(*...) разделяет результаты пробелом.

Альтернатива с явным объединением строк

Кодовая точка ≠ байт. Например, ord("Б") даёт 1041, но при кодировании в UTF-8 эта буква занимает 2 байта. Функция ord() не возвращает «байт UTF-8».

▣ Ситуация из практики

Разработчик создал генератор паролей на random.choice и решил, что этого достаточно. Проверим исходный скрипт перед применением.

Актив: Пароли пользователей. Угроза: Предсказуемая генерация.

◉ Разбираем причинно-следственную связь

Важные риски: слабый источник случайности, недостаточная длина, вывод секретов в журнал, неподходящие требования к составу и отсутствие политики безопасного хранения.

Что проверяем: Перечислить ошибки и подтвердить тестами.

⌘ Python · фрагмент для самостоятельной проверки

import secrets
import string
alphabet = string.ascii_letters + string.digits + "!@#$%"
password = "".join(secrets.choice(alphabet) for _ in range(20))
print("Длина:", len(password))
print("Случайность из secrets:", True)
Ожидаемый результат: Длина: 20 Случайность из secrets: True

Код запускается в Python 3 и использует только стандартную библиотеку. Эксперименты выполняйте на учебных данных и в разрешённом окружении.
