01 / ОСНОВЫ

Что делает случайное число безопасным?

Программа может выдавать выглядящие случайными числа, которые на самом деле воспроизводимы. В криптографии важно, чтобы злоумышленник не мог эффективно предсказать следующую порцию данных.

PRNG · обычная псевдослучайность

random

Алгоритм вычисляет последовательность на основе внутреннего состояния. С тем же seed можно получить те же результаты. Подходит для симуляций, игр и воспроизводимых экспериментов.

CSPRNG · криптографическая стойкость

secrets

Использует криптографически стойкий системный источник. Требования — вычислительная непредсказуемость и устойчивость к компрометации состояния в рамках используемой конструкции.

Главный критерий

Источник

Внешний вид строки ничего не гарантирует: токен с 40 символами может оказаться полностью предсказуемым, если сгенерирован слабым алгоритмом.

Уточнение к слайдам. MT19937 можно восстановить по 624 последовательным полным 32-битным выходам при типовой утечке выходных слов; это не означает, что любые 624 вызова Python random.random() напрямую раскрывают состояние. Криптографическая стойкость не выводится из разнообразия символов.

Модуль secrets

Python · системный генератор 
import secrets

token = secrets.token_bytes(32)      # 32 байта
hex_token = secrets.token_hex(16)   # 32 hex-символа
url_token = secrets.token_urlsafe(16)
choice = secrets.choice("abc123")
number = secrets.randbelow(100)     # 0 ... 99
safe_equal = secrets.compare_digest("a", "b")

token_bytes(n) возвращает n случайных байт; token_hex(n) кодирует n байт в 2n hex-символов; token_urlsafe(n) выдаёт URL-безопасную Base64-строку.

Зачем compare_digest?

При обычном сравнении время выполнения в некоторых обстоятельствах может зависеть от данных. secrets.compare_digest() реализует сравнение, снижающее риск тайминговых атак при подходящих типах входа.

Для паролей нужна специализированная хеш-функция с солью, а не простое хранение паролей или их прямое сравнение как токенов.

Сильный токен = безопасно сгенерирован + достаточно непредсказуем + корректно передан и сохранён + имеет срок действия и политику отзыва.

Байты, строки, кодировки

str содержит Unicode-символы; bytes — неизменяемую последовательность чисел 0–255; bytearray — изменяемую последовательность байт.

Python · работа с байтами 
text = "Привет"
data = text.encode("utf-8")
print(data.hex())
print(data.decode("utf-8"))

raw = bytes.fromhex("ff41")
mutable = bytearray(raw)
mutable[0] = 0
print(mutable.hex())  # 0041

print(ord("A"))  # 65
print(chr(65))   # A

hex и Base64 — способы представления байтов, не шифрование.

XOR · исключающее ИЛИ

Оператор ^ сравнивает биты: результат равен 1, когда биты различаются. Свойства A ^ A = 0 и (A ^ K) ^ K = A позволяют строить простые демонстрации обратимости.

Сам по себе XOR не является безопасным шифром. Повторение одного и того же ключевого потока для разных сообщений уязвимо.

Энтропия · сколько неопределённости?

Если каждый из L символов выбирается независимо и равновероятно из алфавита из N символов, теоретическая энтропия составит H = L · log₂(N) бит.

Для 4-значного случайного PIN: 4·log₂(10) ≈ 13,29 бит. Для случайной строки из 8 символов алфавита 62: 8·log₂(62) ≈ 47,63 бит.

Формула не позволяет вычислить энтропию произвольного выбранного человеком пароля по одной его длине. Она описывает модель равномерной независимой генерации.

Реальные уроки истории

Debian OpenSSL (2008): ошибка в генерации случайности привела к предсказуемым криптографическим ключам (CVE-2008-0166).

Веб-токены: даже длинный токен опасен, если его можно предсказать, он попадает в журналы, не истекает или не отзывается.

Контрольная сумма XOR: позволяет обнаруживать часть случайных изменений, но легко сохраняется при некоторых изменениях данных, поэтому не заменяет HMAC или цифровую подпись.

Как читать класс Python

Python · минимальный пример 
class Token:
    def __init__(self, value):
        self.value = value       # атрибут объекта

    def length(self):
        return len(self.value)  # метод объекта

item = Token("example123")     # конструктор
print(item.length())           # 10

class описывает шаблон, экземпляр хранит собственные данные, self указывает на текущий объект. Атрибут __token затрудняет прямой доступ через механизм переименования имени, но не является защищённым секретным хранилищем.

▣ Ситуация из практики

Проверяем одноразовый код подтверждения: система должна сравнивать его без лишних различий по времени выполнения и не печатать значения в журнал.

Актив: Секреты сессии. Угроза: Утечка через сравнение по времени.

◉ Разбираем причинно-следственную связь

compare_digest уменьшает риск некоторых атак по времени при сравнении строк или байтов совместимых типов. Это лишь часть защиты: необходимы ещё сроки действия, ограничение попыток и безопасное хранение.

Что проверяем: Проверить без вывода секретных значений.

⌘ Python · фрагмент для самостоятельной проверки

import hmac
expected = b"demo-code-123"  # Только учебные данные!
received = b"demo-code-123"
ok = hmac.compare_digest(expected, received)
print("Совпадение:", ok)
Ожидаемый результат: Совпадение: True

Код запускается в Python 3 и использует только стандартную библиотеку. Эксперименты выполняйте на учебных данных и в разрешённом окружении.
