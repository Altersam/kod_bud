1. Что на самом деле делает ООП

Класс — это не «коробка для функций». Он задаёт допустимое состояние объекта и способы, которыми это состояние можно менять.

КлассПравила и шаблон
→
ОбъектКонкретный экземпляр
→
АтрибутыСостояние объекта
→
МетодыРазрешённые операции

Обычный пример

Устройство хранит имя и процент потерь пакетов. Метод вычисляет уровень угрозы.

Python 
class NetworkDevice:
    def __init__(self, hostname, packet_loss):
        self.hostname = hostname
        self.packet_loss = packet_loss

    def threat_level(self):
        if self.packet_loss < 5:
            return "NORMAL"
        elif self.packet_loss <= 20:
            return "DEGRADED"
        return "CRITICAL"

Что здесь важно

  1. __init__ создаёт начальное состояние.
  2. self — ссылка на текущий объект.
  3. Метод анализирует состояние именно этого объекта.
  4. Если состояние меняется, меняется и поведение метода.
Связь с ИБ: объект может представлять учётную запись, токен, сетевой узел, файл журнала или политику доступа.

3. Инкапсуляция: зачем ограничивать прямой доступ

Если любую переменную объекта можно менять напрямую, объект не контролирует собственное состояние. В безопасности это превращается в повышение привилегий, обход валидации и утечки секретов.

4. Name mangling: что происходит с __private

Python меняет внутреннее имя атрибута, чтобы снизить риск случайного конфликта и прямого доступа.

class PasswordVault:
    def __init__(self, password):
        self.__password = password

    def check(self, value):
        return value == self.__password

v = PasswordVault("s3cr3t")

5. @property: атрибут с контролем доступа и валидацией

Снаружи кажется, что мы работаем с обычным атрибутом. На самом деле чтение и запись проходят через методы.

class UserAccount:
    def __init__(self, username, privilege):
        self.username = username
        self.__privilege = 0
        self.privilege = privilege

    @property
    def privilege(self):
        return self.__privilege

    @privilege.setter
    def privilege(self, value):
        if value not in range(4):
            raise ValueError("Уровень 0–3")
        self.__privilege = value

6. Уязвимость: Mass Assignment

Опасный шаблон: автоматически копировать все поля клиентского запроса в объект без белого списка разрешённых полей.

Клиент присылает JSON

{
  "display_name": "Ivan",
  "role": "admin"
}
→

Объект User

display_nameGuest
roleuser
Ожидает изменения.

Почему это опасно

Если сервер доверяет любому полю из запроса, пользователь может передать role=admin, is_staff=true или другой критичный атрибут. Защита — разрешать изменение только явно перечисленных полей.

ALLOWED_FIELDS = {"display_name"}

for key, value in payload.items():
    if key in ALLOWED_FIELDS:
        setattr(user, key, value)

8. Основные тренажёры

Браузер не запускает Python без внешнего интерпретатора, поэтому встроенная проверка анализирует структуру решения: имя класса, методы, ключевые условия и возвращаемые значения.

Тренажёр 1. UserAccount.status()

Создайте класс UserAccount. Конструктор принимает username и attempts. Метод status() возвращает:

  • SAFE, если attempts < 3
  • WARNING, если 3–5
  • BLOCKED, если > 5
Ответ
class UserAccount:
    def __init__(self, username, attempts):
        self.username = username
        self.attempts = attempts

    def status(self):
        if self.attempts < 3:
            return "SAFE"
        elif self.attempts <= 5:
            return "WARNING"
        return "BLOCKED"

username = input()
attempts = int(input())

user = UserAccount(username, attempts)
print(user.username)
print(user.status())

Тренажёр 2. UserAccount.is_blocked()

Этот тренажёр соответствует автопроверке на платформе. Создайте класс UserAccount. Конструктор принимает login и failed_attempts и сохраняет их в атрибутах объекта.

  • is_blocked() возвращает OK, если неудачных попыток 0–2;
  • is_blocked() возвращает BLOCKED, если failed_attempts >= 3.
Важно для автопроверки: не меняйте имя класса, имена атрибутов, сигнатуру конструктора и строки OK/BLOCKED.
Ответ

Код, который нужно отправлять в тренажёр:

class UserAccount:
    def __init__(self, login, failed_attempts):
        self.login = login
        self.failed_attempts = failed_attempts

    def is_blocked(self):
        if self.failed_attempts >= 3:
            return "BLOCKED"
        return "OK"

Как проверить самостоятельно:

user1 = UserAccount("anna", 1)
user2 = UserAccount("ivan", 3)
user3 = UserAccount("petr", 7)

print(user1.is_blocked())  # OK
print(user2.is_blocked())  # BLOCKED
print(user3.is_blocked())  # BLOCKED
Почему работает: состояние объекта хранится в failed_attempts. Метод читает это состояние и классифицирует учётную запись. Граница блокировки — ровно 3 попытки, поэтому используется >= 3.
