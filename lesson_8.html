1. Что на самом деле делает ООП

Класс — это не «коробка для функций». Он задаёт допустимое состояние объекта и способы, которыми это состояние можно менять.

КлассПравила и шаблон
→
ОбъектКонкретный экземпляр
→
АтрибутыСостояние объекта
→
МетодыРазрешённые операции

Обычный пример

Устройство хранит имя и процент потерь пакетов. Метод вычисляет уровень угрозы.

Python 
class NetworkDevice:
    def __init__(self, hostname, packet_loss):
        # Атрибуты описывают состояние конкретного устройства.
        self.hostname = hostname
        self.packet_loss = packet_loss

    def threat_level(self):
        # Метод анализирует внутреннее состояние объекта.
        if self.packet_loss < 5:
            return "NORMAL"

        # От 5 до 20 процентов включительно.
        elif self.packet_loss <= 20:
            return "DEGRADED"

        # Всё, что выше 20 процентов.
        return "CRITICAL"

Что здесь важно

  1. __init__ создаёт начальное состояние.
  2. self — ссылка на текущий объект.
  3. Метод анализирует состояние именно этого объекта.
  4. Если состояние меняется, меняется и поведение метода.
Связь с ИБ: объект может представлять учётную запись, токен, сетевой узел, файл журнала или политику доступа.

Мини-шпаргалка по терминам, которые разбирали на занятии

Начальная настройка объекта: сюда обычно передают данные, которые объект должен запомнить.

def

От слова definition: объявляет функцию или метод. Сам по себе def функцию не запускает.

self

Ссылка на текущий объект. Благодаря ей метод читает и изменяет именно его атрибуты: self.login, self.failed_attempts.

value

Просто имя параметра. Оно не является специальным словом Python: вместо value можно выбрать другое понятное имя.

pass

Пустая команда-заглушка. Ничего не делает и позволяет временно оставить тело функции или класса пустым.

continue и break

Работают в циклах: continue переходит к следующей итерации, а break полностью завершает цикл.

Почему не просто функция?

Отдельная функцияКласс + объект
Получает значения, что-то проверяет и возвращает результат. Хранит состояние объекта и объединяет рядом методы, которые относятся именно к этому состоянию.
Удобна для независимой операции. Удобен, когда одна сущность живёт дольше одного вызова: пользователь, токен, устройство, файл, инцидент.

Поэтому в уроке решения сопровождаются комментариями именно по этому маршруту.

3. Инкапсуляция: зачем ограничивать прямой доступ

Если любую переменную объекта можно менять напрямую, объект не контролирует собственное состояние. В безопасности это превращается в повышение привилегий, обход валидации и утечки секретов.

public

role

Доступен всем. Подходит для некритичных данных.

_protected

_role

Соглашение: «внутренняя деталь». Python не запрещает доступ технически.

__private

__role

Включает name mangling: имя преобразуется внутри класса.

4. Name mangling: что происходит с __private

Python меняет внутреннее имя атрибута, чтобы снизить риск случайного конфликта и прямого доступа.

class PasswordVault:
    def __init__(self, password):
        # Двойное подчёркивание включает name mangling.
        # Пароль считается внутренним состоянием объекта.
        self.__password = password

    def check(self, value):
        # Наружу не выдаём сам пароль.
        # Возвращаем только результат сравнения: True / False.
        return value == self.__password

5. @property: атрибут с контролем доступа и валидацией

Снаружи кажется, что мы работаем с обычным атрибутом. На самом деле чтение и запись проходят через методы.

class UserAccount:
    def __init__(self, username, privilege):
        # username можно читать и менять напрямую:
        # здесь это обычный публичный атрибут.
        self.username = username

        # Реальное значение уровня прав храним отдельно.
        # Начальное безопасное значение — 0.
        self.__privilege = 0

        # ВАЖНО: эта строка вызывает setter ниже.
        # Значение privilege сначала пройдёт проверку.
        self.privilege = privilege

    @property
    def privilege(self):
        # Getter срабатывает при чтении:
        # print(user.privilege)
        return self.__privilege

    @privilege.setter
    def privilege(self, value):
        # Разрешаем только уровни 0, 1, 2 и 3.
        if value not in range(4):
            raise ValueError("Уровень 0–3")

        # Сохраняем значение только после проверки.
        # Правильно: value, а не valuej.
        self.__privilege = value

На занятии этот механизм сравнивался с фильтром: внешнее значение сначала попадает в проверку, и только после успешной проверки записывается во внутренний атрибут. Для пароля, роли или уровня привилегий это удобная модель: вход → проверка → сохранение.
Важно: setter — это валидация и контроль состояния объекта. Сам по себе @property не является универсальной защитой от SQL-инъекций, XSS и других атак; для них нужны отдельные механизмы защиты.

6. Уязвимость: Mass Assignment

Опасный шаблон: автоматически копировать все поля клиентского запроса в объект без белого списка разрешённых полей.

Клиент присылает JSON

{
  "display_name": "Ivan",
  "role": "admin"
}
→

Объект User

display_nameGuest
roleuser
Ожидает изменения.

Почему это опасно

Если сервер доверяет любому полю из запроса, пользователь может передать role=admin, is_staff=true или другой критичный атрибут. Защита — разрешать изменение только явно перечисленных полей.

# Белый список полей, которые клиенту разрешено менять.
ALLOWED_FIELDS = {"display_name"}

# Перебираем поля входящего запроса.
for key, value in payload.items():
    # Критичные поля вроде role сюда не попадут.
    if key in ALLOWED_FIELDS:
        setattr(user, key, value)

8. Основные тренажёры

Браузер не запускает Python без внешнего интерпретатора, поэтому встроенная проверка анализирует структуру решения: имя класса, методы, ключевые условия и возвращаемые значения.

Тренажёр 1. UserAccount.status()

Создайте класс UserAccount. Конструктор принимает username и attempts. Метод status() возвращает:

  • SAFE, если attempts < 3
  • WARNING, если 3–5
  • BLOCKED, если > 5
Ответ
class UserAccount:
    def __init__(self, username, attempts):
        # Сохраняем данные конкретной учётной записи.
        self.username = username
        self.attempts = attempts

    def status(self):
        # 0–2 неудачные попытки: обычное состояние.
        if self.attempts < 3:
            return "SAFE"

        # 3–5 попыток включительно: требуется внимание.
        elif self.attempts <= 5:
            return "WARNING"

        # Более 5 попыток: считаем запись заблокированной.
        return "BLOCKED"

# Считываем две строки входных данных.
username = input()
attempts = int(input())

# Создаём объект и выводим требуемый результат.
user = UserAccount(username, attempts)
print(user.username)
print(user.status())

Тренажёр 2. UserAccount.is_blocked()

Формат именно для тренажёра на платформе: здесь не нужны приватные атрибуты, setter, register_failure() или reset_attempts(). По условию — обычный класс, два атрибута и один метод проверки.

Условие. Создайте класс UserAccount. На вход программе подаются две строки:

  • login — логин пользователя;
  • failed_attempts — целое число неудачных попыток входа.

Конструктор должен сохранить оба значения в атрибутах self.login и self.failed_attempts. Метод is_blocked() должен вернуть:

  • BLOCKED, если failed_attempts >= 3;
  • OK во всех остальных случаях.

После этого считайте обе переменные, создайте объект и выведите только результат метода is_blocked().

Пример входа

4
Пример вывода

Ответ с подробными комментариями 
class UserAccount:
    def __init__(self, login, failed_attempts):
        # login и failed_attempts — значения,
        # которые пришли СНАРУЖИ при создании объекта.

        # Сохраняем login ВНУТРИ конкретного объекта.
        self.login = login

        # Сохраняем число неудачных попыток входа.
        self.failed_attempts = failed_attempts

    def is_blocked(self):
        # Метод работает уже с тем значением,
        # которое объект запомнил в self.failed_attempts.

        # Ровно 3 попытки уже означают блокировку,
        # поэтому нужен оператор >=, а не просто >.
        if self.failed_attempts >= 3:
            return "BLOCKED"

        # Если условие выше не выполнилось,
        # значит попыток 0, 1 или 2.
        return "OK"


# 1. Читаем логин как строку.
login = input()

# 2. Читаем число попыток и преобразуем строку в int.
failed_attempts = int(input())

# 3. Создаём объект.
# Значения попадут в параметры login и failed_attempts
# метода __init__.
account = UserAccount(login, failed_attempts)

# 4. Через точку вызываем метод ЭТОГО объекта.
# Печатаем только то, что требует тренажёр.
print(account.is_blocked())
