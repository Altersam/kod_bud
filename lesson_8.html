Инкапсуляция не равна полномочиям

Инженерная задача

Пользователь отправляет серверу JSON с полями `display_name` и `role`. Если код без проверки копирует все поля в объект, ученик может попытаться назначить себе административную роль. Это типичный сценарий Mass Assignment.

Граница модели

Полномочия на операцию нужно проверять в доверенном серверном коде и применительно к конкретному объекту. Свойства Python помогают управлять атрибутами, но не заменяют авторизацию.

Важно: любой пример в курсе использует искусственные данные. Действия с настоящими сервисами допустимы только при наличии полномочий.

Как взаимодействуют части системы

Вместо магического «объект защищён» разбираем последовательность: кто выполняет действие, какая проверка применяется, что происходит со значением и что фиксируем в результате.

Понятия и пояснения

@property

Доступ к вычисляемому или проверяемому значению как к атрибуту. Часто сочетается с setter, который проверяет диапазон допустимых значений.

Двойное подчёркивание

Имя `__token` преобразуется в `_ClassName__token`. Это защита от случайных конфликтов имён, а не шифрование и не авторизация.

Mass Assignment

Опасность возникает, когда поля запроса автоматически становятся полями модели без списка допустимых изменений.

Белый список полей

Система явно перечисляет поля, которые можно обновлять через конкретный endpoint. Роли и права обычно редактируются отдельным защищённым процессом.

Секреты в объектах

`repr()`, сериализация и логи могут случайно раскрыть пароль или токен. Не включайте чувствительные значения в публичные строковые представления.

Разделение ответственности

Модель отвечает за валидное состояние, сервис авторизации — за права субъекта, обработчик запроса — за формат входных данных.

Практика Python: запусти и объясни

Каждый фрагмент запускается в Python 3 без сторонних зависимостей. Попробуйте изменить входные данные и предсказать результат до запуска.

01. Использование @property с валидацией

class UserScore:
    def __init__(self, value):
        self.value = value

    @property
    def value(self):
        return self._value

    @value.setter
    def value(self, new):
        if not isinstance(new, int) or not (0 <= new <= 100):
            raise ValueError('score must be 0..100')
        self._value = new

score = UserScore(75)
print(score.value)
try:
    score.value = 900
except ValueError as exc:
    print('Отклонено:', exc)
75 Отклонено: score must be 0..100
Разбор. Setter защищает согласованность состояния при обычном использовании API, но не является контуром защиты от запуска произвольного Python-кода.

02. Mass Assignment: безопасное обновление профиля

profile = {'display_name': 'Алексей', 'role': 'student'}
request = {'display_name': 'Александр', 'role': 'admin'}
EDITABLE = {'display_name'}

for key in EDITABLE & request.keys():
    profile[key] = request[key]
print(profile)
{'display_name': 'Александр', 'role': 'student'}
Разбор. Поле role проигнорировано. Настоящий сервер дополнительно проверяет тип, размер и содержимое каждого разрешённого поля, а также принадлежность профиля субъекту.

03. Скрываем секрет из представления объекта

class ApiClient:
    def __init__(self, token):
        self._token = token

    def __repr__(self):
        return 'ApiClient(token=<redacted>)'

client = ApiClient('demo-token-not-real')
print(client)
ApiClient(token=<redacted>)
Разбор. Такое представление снижает риск случайного вывода секретов, но пароль всё равно не следует хранить в ненужных местах или логировать.

▣ Ситуация из практики

При обновлении профиля пользователь передал поле role=admin вместе с именем. Приложение не должно автоматически переносить каждое поле в объект.

Актив: Атрибуты профиля. Угроза: Mass Assignment.

◉ Разбираем причинно-следственную связь

Не стоит делать setattr(user, key, value) для всех пришедших от клиента полей. Проверять нужно разрешённые поля, права субъекта и ограничения значений.

Что проверяем: Проверить запрет на изменение роли.

⌘ Python · фрагмент для самостоятельной проверки

profile = {"display_name": "Ира", "role": "student"}
incoming = {"display_name": "Ирина", "role": "admin"}
editable = {"display_name"}
for key in editable & incoming.keys():
    profile[key] = incoming[key]
print(profile)
Ожидаемый результат: {'display_name': 'Ирина', 'role': 'student'}

Код запускается в Python 3 и использует только стандартную библиотеку. Эксперименты выполняйте на учебных данных и в разрешённом окружении.
